# 08. 화면 흐름·데모 대본

> 버전: v1.0 · 기준일: 2026-08-10 · 상태: **발표·QA 최종본**

## 1. 데모 메시지

> 이 서비스는 주문을 자동 확정하는 시스템이 아니라, 제약을 만족하는 편성안과 미배정 이유, 다시 검토할 수 있는 조건을 보여 주는 운영 지원 도구입니다.

## 2. 화면 흐름

```mermaid
flowchart LR
    A["시나리오 대시보드"] --> B["입력·검증"]
    B --> C["후보 검토"]
    C --> D["기본 편성·화차 배치"]
    D --> E["대안 비교"]
    E --> F["결정 기록"]
```

## 3. 화면별 요구사항

| 화면 | 반드시 보여 줄 정보 | 핵심 행동 |
| --- | --- | --- |
| 시나리오 대시보드 | 기준 시각, 데이터 출처 배지, 주문·슬롯 요약 | 정본 시나리오 열기 |
| 입력·검증 | 필수값 누락, 시간 오류, 가정 ID | 오류 주문 분리 확인 |
| 후보 검토 | 적합 운행, 제외 사유, 납기 여유 | 주문별 근거 보기 |
| 기본 편성 | 배정표, 화차 슬롯 배치도, 지도, 미배정 사유 | 기본안 비교 |
| 대안 비교 | 변경 항목, 전후 상태, 영향 주문, 협의 필요 사항 | 다음 운행/대체 터미널 대안 실행 |
| 결정 기록 | 채택·보류·반려, 사유, 실행·정책 버전 | 결정 저장 |

지도는 가상 화주의 출발/도착 좌표와 선택된 터미널을 연결해 맥락을 보여 준다. 도로 시간이나 최적 경로를 계산한 것처럼 표현하지 않는다.

## 4. 5단계 데모 대본

### 장면 1 — 입력 검증

- 행동: `ORD-006`의 누락된 총중량을 확인한다.
- 발표: “모르는 값을 임의로 채우지 않고 계산 대상에서 분리합니다.”

### 장면 2 — 후보와 하드 제약

- 행동: `ORD-007`의 높이 초과와 `ORD-008`의 터미널 취급 불가 사유를 확인한다.
- 발표: “추천 점수보다 먼저 시간, 규격, 중량, 터미널 제약을 확인합니다.”

### 장면 3 — 기본 편성

- 행동: 화차 배치도에서 `ORD-001~003`의 슬롯 배정을 보고 `ORD-004`의 미배정을 선택한다.
- 발표: “ORD-004는 불가능한 주문이 아니라, 현재 슬롯 경합으로 선택되지 않은 주문입니다.”

### 장면 4 — 조건부 대안

- 행동: `ORD-005`에 대안 전용 다음 운행을 적용하고 기본안과 변경 차이를 확인한다.
- 발표: “대안은 사전 승인된 변경만 적용하며, 원래 안을 덮어쓰지 않고 새 시나리오로 보존합니다.”

### 장면 5 — 운영자 결정

- 행동: 기본안 또는 대안을 보류하고 협의 필요 사항을 기록한다.
- 발표: “최종 결정은 운영자가 내리고, 그 판단에 사용한 입력과 정책 근거도 함께 남습니다.”

## 5. 데모 전 점검표

- [ ] 모든 화면에 `DEMO_ASSUMPTION` 또는 출처 배지가 있다.
- [ ] `확인 필요`, `편성 가능`, `편성 가능·미배정`, `조건부 대안 있음`, `불가`가 모두 보인다.
- [ ] 기본안에 대안 전용 서비스가 포함되지 않는다.
- [ ] 화차 배치도와 배정표의 슬롯 ID가 일치한다.
- [ ] 지도에는 실제 주소·개인정보가 없다.
- [ ] 비용 절감·탄소 절감·배정 확률·실운영 가능성을 주장하지 않는다.
- [ ] `validator_status = PASS`인 결과만 채택 선택을 제공한다.

## 6. 결과보고서용 캡처 목록

1. 제품 한 문장과 전체 흐름
2. 입력 검증·출처 배지 화면
3. 후보 검토와 제외 사유 화면
4. 화차 슬롯 배치도와 배정표
5. 미배정 주문의 `CAPACITY_CONFLICT` 상세
6. 기본안·대안 비교와 `change_set`
7. 결정 기록과 검증 통과 상태

## 7. 화면·API 연결 계약

| 화면 | 데이터 원천 | 필수 컴포넌트 | 성공 조건 |
| --- | --- | --- | --- |
| 대시보드 | `scenario.json` | 가정 배지, 운행·슬롯 카운트 | `DEMO_ASSUMPTION` 표시 |
| 입력·검증 | `POST /scenarios/{scenario_id}/validate` | 오류 목록, 필드명, 원인 | `ORD-006`만 `REVIEW_REQUIRED`, 시나리오는 `READY_TO_SOLVE` |
| 후보 검토 | 검증 결과 | 후보 슬롯 수, 제외 사유 | `ORD-007`·`ORD-008` 근거 |
| 기본 편성 | `GET /runs/{run_id}` | 배정표, 화차 슬롯 배치, 지도 | `ORD-004` 경합 설명 |
| 대안 비교 | `POST /runs/{run_id}/alternatives` | `change_set`, `assignment_deltas`, 영향 목록 | `ORD-005` 또는 `ORD-008` 대안; 없음은 `NONE` |
| 결정 기록 | `POST /runs/{run_id}/decisions` | 상태 선택, 사유 입력 | PASS 결과만 채택 가능 |

## 8. 발표 금지 문구

- “실제 운행이 가능합니다.”
- “비용 또는 탄소를 절감합니다.”
- “AI가 95% 확률로 편성을 보장합니다.”

대신 “정본 목업 시나리오에서 정의된 제약을 지키는 배정안과 대안을 계산합니다.”라고 말한다.

## 9. UI 예외 상태 계약

| 상황 | 화면 행동 | 허용 행동 |
| --- | --- | --- |
| 검증 중 | 결과 표 대신 진행 상태와 대상 시나리오 표시 | 취소 또는 재조회 |
| `REVIEW_REQUIRED` | 누락 필드와 주문 ID를 고정 표시 | 계산 대상에서 자동 제외 |
| `alternative_state = NONE` | “대안 없음”과 탐색 범위를 표시 | 새 정책·입력 없이는 재시도 비활성 |
| `SOLVED_FEASIBLE` | “실행 가능 안·최적성 미확정” 배지와 종료 사유 표시 | 보류·반려만 가능 |
| `validator_status = FAIL` | 위반 코드·대상 자원 표시 | 채택·결정 저장 비활성 |
| API 오류 | 오류 코드·trace ID·재시도 가능 여부 표시 | 재시도 또는 이전 결과 보기 |
